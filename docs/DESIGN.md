# 设计文档

本页描述当前数据模型、几何算法、状态与模块结构。操作说明见 [功能与操作](FEATURES.md)，未覆盖能力和验证边界见 [范围与限制](ROADMAP.md)。

技术栈为 React 19、TypeScript strict、Three.js、@react-three/fiber、Zustand 和 Vite。应用入口和分享载入位于 `src/main.tsx`，布局和全局快捷键位于 `src/App.tsx`。

## 数据模型与坐标

采用右手坐标系，Y 轴向上，长度单位为毫米。零件及设备定义在 `src/store/useStore.ts`。

| 类型 | 位置和朝向语义 | 主要字段 |
|---|---|---|
| `ProfileData` | `position` 为中心线起点，局部 +Z 指向终点 | `spec`、`length`、`quaternion`、`fixedTrims`、`miterCuts`、`holes` |
| `ConnectorData` | 原点和局部轴由各连接件的模型定义 | `type`、`series`、`profileSpec`、`mountSeries`、`position`、`quaternion` |
| `PanelData` | `position` 为板中心，局部 X 为宽、Y 为高、Z 为厚 | `width`、`height`、`thickness`、`material` |
| `EquipmentData` | `position` 为本体中心，局部 X/Y/Z 为宽高深，+Z 朝前 | `name`、`width/height/depth`、`clearance` 六面非负预留 |
| `FittingData` | `position` 为开口中心，局部 X 横跨开口、Y 向上、+Z 朝外 | `kind`、`width/height/depth`、`frame`、`hinge`、`hingeType`、`overlay`、`swing`、`open`、`stacked`、`meeting` |

各类零件都有唯一 ID 和可选的 `locked`。型材规格为 2020、2040、3030、3040、4040、4040-B6（4040 为 I8，4040-B6 为 B6）；板材及构件材质为 `mdf`、`ply`、`acrylic`、`alu`。

板件和构件默认独立，可通过 `openingBinding` 关联明确指定的洞口表面。生成的支撑和角码可分别通过 `runnerBinding`、`supportBinding` 跟随来源部件。`miterCuts` 和 `holes` 可随工程数据保存，当前渲染及实体导出不据此生成加工孔或斜切面。

2020 B6、2040 B6、4040 B6、3030 B8、4040 I8 的截面来自 Motedis 厂家 CAD，3040 仍为未核验通用截面。连接件的型号、尺寸来源、紧固件及加工限制集中在 `connectorHardware.ts` 和 `connectorAccessoryReferences.ts`；板件间隙、挠度参数等仍是程序采用的设计参数。

## 型材实体与接头

### 中心线及实体端面

中心线终点由 `position + quaternion × (0, 0, length)` 得到。接头算法为每端计算 `trim`，实体起点沿局部 +Z 移动 `start.trim`，下料长度为：

```text
cutLength = length - start.trim - end.trim
```

`trim` 可为负，表示端部延伸。渲染、干涉检查、BOM 和型材导出使用实体起点与下料长度。

`fixedTrims: { start, end }` 保存端面相对中心线端点的裁切偏移。明确参考面的绘制用它记录已确定的端面；移动、旋转和复制保留既有实体尺寸。长度编辑保留裁切偏移，并按新中心线长度计算新下料长度；删除邻件不会重算其他已固定件。

工程 `throughRule` 支持：

- `rails`：默认优先级 X > Z > Y。
- `posts`：优先级 Y > X > Z。

自动接头按方向优先级、对接或贯通关系及对方截面计算裁切；接头识别有几何容差。修改规则或「重新裁切接头」清除未锁定件的固定端面后重算，锁定件保留现有实体尺寸。规则随工程保存并进入撤销快照。

实现位于 `geometryCore.ts`、`jointUtils.ts`、`profileFaces.ts`。

### 新建与落地

`profileFactory.ts` 按两个中心线点创建型材，最小创建长度为 10mm；普通坐标保留到 0.001mm、中心线长度保留到 0.01mm。

`faceAlign.ts` 分别处理自动贴面对齐和明确选面约束。自动对齐尝试截面转向及侧移；明确选面时以参考构件的实际面计算新端面，保留已有参考几何，并返回未满足约束的原因。预览和提交使用同一落位计算。

新建水平型材按截面半高处理落地位置。手势移动和微调使用型材最低点限制组位移；属性面板手输坐标不进行落地钳制。相关计算使用中心线位置和截面朝向。

## 拾取与编辑

`pickUtils.ts` 处理端点、构件中心线、表面与工作面落点，以及世界轴的屏幕投影解析。非零工作面限制候选高度，默认地面允许吸附高处构件。

`pickDrawingStart.ts` 为世界 X/Z 轴方向的水平型材计算起点齐边：支承面决定新端面位置，端面或 T 接缝决定侧面位置。T 接缝处射线穿过槽口时，按指针所在的有限上、下面恢复支承面，端边吸附须同时满足 20mm 和 12px 范围。起点只吸附到当前可见构件，裁切仍按完整模型计算。`drawPreview.ts` 与 `drawContacts.ts` 提供预览几何和实际接触区域。

选择使用真实网格射线命中及屏幕空间候选。`screenPick.ts` 分别计算连接件各块实体的投影轮廓，保留实体之间的空隙，并在轮廓外提供 20px 容差。`frontmost.ts` 使真实网格命中优先于容差候选，并处理剖切排除；`PointerRouter.tsx` 统一悬停、选择及拖动目标，Shift 按下后等待单击或拖动：松开时切换多选，超过 5px 时进入自由拖动；`Tab` / `Shift + Tab` 可轮选重叠处的其他候选。

`editOps.ts` 提供零件及设备的组平移、旋转、复制、镜像、阵列和属性更新：

- 平移和旋转修改明确选中的未锁定件，并更新它们的关联部件；单独变换连接件时解除其支撑关联，与宿主一起变换时保留关联。
- 复制、镜像和阵列可使用锁定来源，副本使用新 ID 并解除锁定。
- 旋转中心由所选型材实体端点、连接件原点、板心、设备本体中心和构件当前包围盒中心计算；单根型材可使用实际起端或终端。
- 镜像平面经过整个工程的计算中心：中心由型材中心线端点和其他零件原点的坐标包围范围求得。反射朝向保持模型的截面或板材对称关系，门的左右铰链边及左右会合边随之交换。三维角码按镜像目标处的可用安装面重新定位并提示；无可用位置时整次镜像取消。
- 阵列沿世界轴生成最多 50 组副本，间距绝对值至少 1mm；若型材或设备副本进入地面以下，全部副本按同一位移抬升。
- `liveParts` 过滤锁定项并校验批量字段；是否创建快照由 `pushHistory` 参数决定，默认为 `false`。调用者在首次真实合法变更时请求快照，后续预览不重复请求。

移动吸附由 `dragSnap.ts` 计算，面关系由 `editAlignment.ts` 提供。按住 Shift 可解除移动吸附；端面拉伸使用独立计算，不采用移动吸附参考线。

`connectedTo` 按型材端点到其他中心线的 30mm 邻近关系遍历；它是框架归属和连通选择的几何启发式，不验证实际螺栓连接。连通选择当前只选型材。

## 连接件模型

`connectorCatalog.ts` 定义 14 种连接件的标签、模型轴和落位类别。`connectorHardware.ts` 汇总按型号核验的实尺寸、来源、紧固件和加工要求。几何接口保留内部归一化与实例缩放，但两者抵消后始终是该 SKU 的实际毫米尺寸；缺少系列型号时显示已知参考件实尺寸并禁止宣称已核验安装，不按比例创造型号。端盖另以完整 `profileSpec` 匹配截面；共用槽 8 内角码以 `mountSeries` 记录两臂各自宿主槽系。

`fit` 定义推断方式（角接、端面、贴面、自由放置），`seat` 定义具体落位模型（内角、外侧板、端面、表面）。两者共同决定位置和朝向。

`specCompat.ts` 枚举共面安装面和槽线。`bracketSeat.ts` 的 `sharedSlotLines` 枚举全部公共槽线，`connectorSeatsAt` 枚举附近垂直构件组合，再按命中面和指针距离排列位置。连接件以可见型材裁切后的外包络拾取安装面，允许指针穿过槽口及端面芯孔；剖切隐藏的交点不参与拾取。贴面件沿外表面命中点定位，端面件吸附到实际裁切端面；角接件另以中心线投影点搜索接头，以外表面点排序槽位。安装和碰撞仍检查实际实体。平板候选包含共面面、两侧法向、槽线组合及 T 板横梁角色；三维角码要求三根 4040 I8 的实际直切端面围成 40mm 角块空间。`auditBrackets` 使用目录定义的螺栓点及法向，按实际裁切范围检查安装面、槽线及系列。

`connectorSupport.ts` 检查候选角接件的型号、安装面、槽位和对两根已裁切型材的实体干涉，供兼容提示、接头修整及补齐型材共用。邻近中心线只提供搜索范围；没有可用角接件时，只有实际裁切包围盒接触，或每个分离轴上的间隙均不超过 0.5mm，才报不适配。已安装的三维角码只有在三个端面均有效且无干涉时，才以实际支承构件替代两两角接件检查；三个端孔均须加工 M8 内螺纹，缺支承或位置错误仍保留提示。

`connectorPlacement.ts` 为手动安装、重新安装、拖动吸附和自动补齐提供相同的占位和干涉检查。单件拖动以 0.1 mm 定位；单轴吸附限定其他轴坐标与朝向，近距离槽位保持稳定，避免指针抖动时反复切换。板材固定件保留专用元数据，不参与通用安装位吸附。安装身份由类型、系列及变换后的孔位和法向组成，对称臂交换视为相同位置；重复放置不产生历史。候选状态区分已有连接件、其他构件干涉、设备预留冲突、缺少安装面及没有已核验型号。所有外贴板、合页和轴承座均须满足完整孔组的槽线及宿主支承。画布候选还要求全部宿主在当前装配步骤可见、安装点未被剖切；过滤显示候选时，裁切及碰撞仍使用完整工程。切换装配步骤或剖切面会解除固定节点，提交时再次检查可见性。

`ConnectorThumbnail.tsx` 读取由场景完整网格离线生成的 168px PNG，覆盖 14 类连接件的 20/30/40 系列。图像文件带内容哈希，单元测试检查源文件摘要与图像内容，生成命令见[缩略图说明](../public/connector-thumbnails/README.md)。首屏不执行模型投影和图片编码。侧栏默认只显示当前形状，展开时显示完整选择器，选择或按 Esc 后收起。名称和安装说明通过悬停及键盘聚焦的浮动提示展示。`DrawingHandler.tsx` 默认使实体预览跟随鼠标，并吸附到可安装候选；画布点击放置后保持跟随。位置按钮、构件组合筛选、`Tab` / `Shift + Tab` 轮选及面板放置会固定当前节点，便于旋转视图检查；解除固定后继续跟随。预览高亮关联型材和安装面。`ConnectorEditor.tsx` 提供位置和角度编辑，并为角接件提供重新安装操作；`ConnectorEditPreview.tsx` 显示临时预览；确认时重新校验并排除自身占位。临时预览不进入工程数据。

`autoConnect.ts` 通过 `jointPartnersAt` 查找端点的所有垂直伙伴，按构件组合和实际安装孔位去重。每个候选分别验证；同槽的不同侧在不干涉时可同时安装。`connectorRecovery.ts` 先对所选类型的失位件搜索 20 mm 内同型号同朝向的安装位，仅在目标唯一且无干涉时调整；有效件、锁定件及板材固定件不移动，其余问题保留并报告。随后补齐缺件，修复和补齐使用同一次工程事务。端盖按匹配截面的自由直切端落位，M8 调节脚可直装 3030 B8 / 4040 I8 朝下端，或通过专用加工转接板安装于 4040 B6 朝下端；脚轮使用 M8×25 沉头螺钉直装 3030 B8 / 4040 I8 朝下端。贴面件不批量推断。

`connectorGeometry.ts` 为显示、拾取和 STEP 提供同一网格。Motedis L 角码、内角码、槽螺母、端盖及脚轮优先使用原厂 STEP；加强角码和三维角块按厂家尺寸建模，遗漏的圆角、铸造腔和螺纹细节列在型号限制中。内角码保留原厂不对称臂长、T 形肩部及根部退让，使用两颗顶丝锁槽，无 T 型螺母。槽 6 型号仅支持 B6；共用槽 8 型号支持 B8/I8，包括按每臂槽唇厚度独立设置埋深和顶丝位置的 30/40 混接。

`connectorCollision.ts` 用分块凸体检查连接件；角码的翼板、筋、定位凸台和内角码肩部分别建块，避免用整体包围盒填满开口。型材使用厂家截面轮廓及芯孔三角剖分后的挤出实体，先用保守包围盒筛选，再按需构造可能接触的三角棱柱；槽唇、扩腔和槽底都参与检查，内角码及槽螺母的宿主还须匹配方向、槽线和安装面。圆弧及孔洞的局部碰撞近似采用保守包络。端盖卡脚和调节脚的螺纹接合只对已核验宿主应用局部安装配合，其他物体仍检查实体。算法不模拟完整插入路径或工具可达性。

凸体的分离轴由局部顶点和实际缩放计算；不同实例复用这组轴，再按各自姿态旋转到世界坐标。局部顶点或缩放变化会重新计算，实例的顶点、轴和碰撞结论互不共享。

调节脚采用 Motedis BD40-8x50 的 M8 螺杆，展示为旋入 10 mm 的姿态；4040 B6 分支使用 8 mm 厚加工板和四颗 M6×20 沉头螺钉，按四芯孔及截面转角定位，底盘和锁紧螺母整体下移 8 mm。脚轮采用 Motedis 10146 的完整厂家模型，M8×25 螺钉旋入型材 8.36 mm。4040 B6 端盖使用四只原厂 2020 盖，只有标记为卡脚的碰撞块获得压入配合余量。完整 `profileSpec` 贯穿安装、BOM、OBB 及碰撞缓存，保持同为 40×40 的 B6 / I8 截面可区分。具体来源和加工图见 [配件说明](CONNECTOR-ACCESSORIES.md)。

板材固定由 `panelMounts.ts` 生成两种候选：内嵌水平板通过 20/30 系列连接片跨接横梁；外贴板通过穿板螺栓连接 B6/B8 槽螺母。`panelMount` 保存板材 ID、型材 ID、间距、板厚及可选 `mode: direct`。支持 2020/2040 B6、4040 B6、3030 B8；3040 拒绝适配。`attachPanels.ts` 检查完整装配，必要时沿槽偏移一个系列宽度；同孔位裸螺母不计为已完成安装。`panelMountGeometry.ts` 与 BOM 共用 M5/M6 尺寸及螺栓长度计算；`panelDrilling.ts` 将 Ø5.5/Ø6.6 孔位用于显示和 STEP。移动后重新检查两侧宿主支承与干涉。`panelFastening.ts` 检查固定覆盖：水平板必须四边都有至少两件有效固定件、孔距覆盖半条边长且距边不超过 25 mm；外贴板的四个外侧象限均须有有效固定点。此检查不表示承重认证。JSON v10 和分享链接 v9 保存关联与模式，复制完整组合时重映射 ID。

## 板件与可动构件

### 板件生成

`panelOps.ts` 根据选择的薄轴确定板面方向。覆盖板取选中型材的实际实体外包范围；嵌入板按选中边界，必要时补查连通框架的开口边界。水平板下表面位于梁顶，竖板放在推断的外侧。

生成结果默认为独立 `PanelData`。关联洞口后，尺寸与位置由边界、留量和所在面计算，厚度与材质仍可编辑。

### 固定开口与朝向

`fittingOps.ts` 根据所选型材确定开口，柜门通常选同侧两柱，抽屉选四柱以定义深度。

归属范围来自连通型材，不回退到整个场景。朝向结合选择的共面轴、背板及前后金属分布推断；已有构件证据使用其固定开口 OBB，并检查该开口与本框架及所选前平面的关系。证据不使用活动门叶或抽屉的当前开度。

覆盖门的尺寸依据所选开口计算；嵌入门和抽屉还以相关水平梁内表面限制高度。构件的 `frame` 保存前方框架厚度，局部 +Z 为开启方向。

拆分适用于开口宽度至少 120mm、尚无会合边的左右铰链单门。按原开口的局部 X 方向分成两半，保留原开口外边，左右门分别在外侧设铰链。每扇保存自己的开口中心、半宽及 `meeting: 'left' | 'right'` 会合边，原门关联洞口时，两扇门继承对应的宽度区间。拆分替换原门并使用一次工程事务，不增加中柱或改变框架。

### 洞口关联

`openingBindings.ts` 按用户指定的型材内表面解析洞口。引用保存型材 ID、局部轴和正负面；左、右、底、顶、前面必选，后面与固定深度二选一。候选只来自明确选中的型材及当前已引用来源，不自动扩展到邻近框架。

门用宽度起止比例分配洞口；抽屉保留自身高度和底部偏移。板件指定所在面、四边毫米留量及向外偏移。支撑跟随抽屉侧面及前后偏移，角码跟随支撑端点的局部变换。依赖按型材、门抽屉/板件、滑轨支撑、支撑角码的顺序计算，不允许派生支撑反过来作为洞口来源。

编辑先计算完整候选及贯通规则，再校验尺寸和锁定状态。任何派生结果无效或改变锁定部件，整次操作拒绝且不生成历史；关联的尺寸和姿态不能单独覆盖；独立编辑支撑角码时由编辑操作显式解除其关联。删除来源保留派生件上次几何及引用，界面提示失联，允许重新关联或解除。

完整复制所选关联关系时重映射来源 ID；仅复制派生件时解除外部引用。阵列各份分别映射，镜像同步变换局部面、方向和左右参数。保存、分享、撤销和重做保留关联。

### 前板与抽屉箱体

`fittingGeometry.ts` 的 `fittingParts` 同时提供渲染、BOM、板材下料及实体导出的板件尺寸。

前板厚度为 18mm。全盖模型盖量为 18mm、半盖为 9mm，外边再扣 3mm 缝；嵌入边直接内缩 3mm。双开门的 `meeting` 边和叠放抽屉的相邻边各内缩 1.5mm，成对会合后留 3mm 缝。前板中心按各边的盖量差调整，铰轴、拉手、活动实体及板材清单使用该实际前板。

左右分仓抽屉各自保存独立开口。侧面安装间隙从每个开口计算，不能把包含中柱的总净宽直接平分。电视柜示例使用 20mm 中间安装梁及半盖抽面，左右抽面之间留 8mm。厨房地柜和独立衣柜各有一列上下两抽，净宽分别为 930mm、840mm，抽面分别为半盖、嵌入。界面没有自动绘制抽屉分仓框架的操作。

覆盖前板背面位于局部 `depth/2 + frame`；嵌入前板前面位于同一平面，厚度向内。门轴位于实际前板前面的安装边，开门变换为绕该轴向外旋转。

`drawerLayout.ts` 解析 `FittingData.drawer`，为几何、尺寸校验、滑轨检查和 BOM 提供相同的箱体尺寸及行程。侧间隙、箱板厚度、底板厚度及后部间隙默认分别为 12.5、15、15、20mm；箱高为 `max(40, height - 26)`。后缘取后部间隙，前缘取前板背面。后部间隙为默认值且未配置轨长和行程时，开启行程为 `max(0, depth - 30)`；改变后部间隙或指定轨长后，默认行程不超过实际轨长。

补强条沿抽屉局部 Z 方向排列在底板下方，数量为 0–4，底板随条高上移。每块构件板件都有独立且稳定的 `key`。`drawerSupports.ts` 检查所选抽屉缺少的安装面，只添加具有前后连接位置的支撑和对应连接件；每只抽屉整体成功或不变，全部成功结果一次提交。

这些参数可按五金尺寸设置；程序不提供厂商型号库或多节滑轨机构模型。

构件校验同时检查开口尺寸与抽箱空间，覆盖新建、属性编辑、实时预览、批量事务、存档和分享。数值输入先按精度舍入再校验；无效批次不写入状态、不生成撤销快照。几何函数仍可用于计算草稿，但进入工程的抽屉必须生成完整箱体。

### 铰链、开度及拉手

`open` 为 0–1，表示关闭到最大开启。界面角度预设为 90/95/110/135/165/180°，JSON 校验允许 `0 < swing <= 180`。几何函数中的型材合页上限为 270°，当前界面及可保存工程不提供该角度。

杯铰和型材合页按安装边长度取 2/3/4 个，长排合页为一条；该数量规则未包含门重和实际五金承载。

开度通过 `setFittingOpenings` 统一更新，允许操作锁定构件，保留撤销和重做记录。

`fittingSolids` 只生成构件板材的活动 OBB。拉手随前板运动，铰链显示模型位于固定安装边，两者都不加入板材碰撞实体；拉手也不进入 BOM、DXF 或 STEP。BOM 中的滑轨和铰链行由构件参数生成。

## 设备占位

`EquipmentData` 保存用户输入的本体尺寸和六面预留。`equipmentGeometry.ts` 分别生成本体 OBB 和扩展后的安装空间 OBB；不对尺寸进行厂商规则推导。扩展盒中心偏移为 `[(right-left)/2, (top-bottom)/2, (front-back)/2]`，随设备四元数旋转。

`equipmentChecks.ts` 对设备本体、预留空间与材料实体逐对做分离轴检查，接触容差为 1mm。同一对对象优先报告本体干涉，否则报告安装预留不足。设备对设备检查本体及各自预留对另一实体，预留之间允许重叠。使用门抽当前开度，不计算连续运动或设备进场路径。

设备参与选择、变换、历史、日志、保存和分享，预留线框不参与拾取。自动保存比较设备引用，预留修改会触发写入。设备不进入 BOM、下料或 CAD 实体导出；旧工程缺少设备集合时补为空数组。

建议构件、连接件安装及自动补齐滑轨支撑使用设备几何过滤候选。自由绘制及变换保留干涉提示机制。

## 检查与估算

| 模块 | 当前方法与范围 |
|---|---|
| `analysis.ts` / `obb.ts` | 实体 OBB 分离轴测试，先按轴向范围筛候选；连接件再按分块实体检查。型材间、连接件之间及连接件对板材容差 1mm；连接件对型材采用 0.15mm（核验的攻牙/压入配合仅对对应局部另设容差），其余板材相关检查容差 3mm |
| `fittingGeometry.swingClashes` | 仅检查门扇间的角度采样，步长不超过 1°；包含同步运动及另一门关闭、半开、全开 |
| `shelfSupport.ts` | 对水平板底面和型材实际顶面求接触，在边内 25mm 带中核对单面至少 70% 边长覆盖 |
| `runnerMount.ts` | 在抽屉局部坐标核对两侧朝向开口的安装面：距侧边不超过 3mm、有效高度至少 10mm，并满足连续深度覆盖或前后立柱条件 |
| `deflection.ts` | 以接触支点估算简支跨中和悬挑端集中载荷及自重，使用内置截面参数；`span/sag < 200` 时提示 |
| `repairJoints.ts` | 先尝试截面转向，再试侧移；按接头、碰撞及连接关系评分筛选步骤 |
| `assembly.ts` | 按几何接触、高度及零件类别生成分步浏览次序 |
| `suggest.ts` / `suggestGate.ts` | 从现有构件生成重复、连接和承托候选，并按当前工程检查候选 |

补齐型材时，碰撞检查覆盖候选和裁切发生变化的既有构件，并与添加前的冲突比较。同一次搜索复用尺寸和姿态未变的实体包围盒；工程数据或贯通规则改变后清除搜索缓存。结构候选按型材、板件、搜索范围和贯通规则缓存生成数据，最多保留 8 组；每次搜索仍重新准备候选并执行接头、支撑、连接件和设备校验。

侧栏和建议器复用同一工程的连接件安装审核及诊断详情。缓存按型材与连接件的规格、姿态和实际裁切数值匹配；新增候选仍单独审核。

常规干涉检查使用门抽屉的当前开度，不连续扫描它们与其他零件的全部运动。位于关闭门后面的可动构件按先开外门的假设略过部分碰撞对；同一构件自身板件之间也不报干涉。

层板检查不覆盖倾斜板或未建模的托件。滑轨检查不验证孔位、螺栓、载重和型号。挠度不计算接头刚度、整柜稳定或实际产品截面差异。采样、装配步骤及零干涉结果均不能证明完整实物装配或承载能力。

侧栏汇总检查结果；CSV、DXF、STEP 和装配说明 HTML 下载完成后通过提示显示待核对项，不阻断下载或要求导出确认。

## 状态、历史与持久化

`useStore` 管理型材、连接件、板件、构件和设备五类集合、工程贯通规则、选择集及 `past/future`。工程快照包含几何与规则，不保存选择；撤销重做后保留仍存在的选中 ID。历史最多 50 步，不持久化。

`commitDocument` 一次替换传入集合并创建一次历史快照，可同时指定选择集。`commitTransform` 批量提交五类集合的更新；`updateParts` 用于连续预览，一次手势在首次有效变化时拍快照。

`useToolStore` 保存手持零件、绘制与拖动态、工作面、查看、测量、剖切、装配步骤、零件编号显示、相机请求及语言等运行时状态，不持久化。查看模式禁用设计编辑和撤销重做；开合仍可模拟。

工程几何与规则通过 `documentPersistence.ts` 写入 localStorage。选择和历史变更不序列化工程，连续变更合并为 180ms 延迟写入；页面隐藏或离开时尝试刷新待写数据。写入成功才更新已保存快照，失败保留最新待写内容。`AutoSaveStatus.tsx` 显示保存状态，并提供重试和下载当前工程的入口。不可解析的原始存档另存恢复副本，由 `RecoveryNotice.tsx` 提供下载和清除入口。

`opLog.ts` 独立持久化最近 400 条设计差异，覆盖零件、设备及规则，排除 `open`。拖动和端面拉伸按手势归并日志；开合不创建设计历史，JSON 和本地工程仍可保存当前开度。

## 工程文件与导出

`document.ts` 校验及序列化 JSON v10：五类集合、唯一零件 ID、有限坐标、有效四元数、尺寸、机制枚举、会合边及贯通规则。当前工程保存和载入只校验数据，保留既有抽面尺寸与叠抽标记。无版本及 v1–v5 数据导入时，由 `migrate.ts` 为旧构件补框架厚度和相邻抽屉标记；解析结果及本地存档带工程版本，防止重复迁移。缺省贯通规则为横梁贯通。

`projectFile.ts` 根据浏览器文件选择 API 提供打开、保存和另存。打开仅在浏览器不支持原生选择 API 时回退到普通文件输入；取消选择直接结束打开操作，选择或读取失败显示导入错误，均保留当前工程及保存目标。工程验证通过后才替换几何及文件目标。保存 API 不可用或写入失败时回退为下载文本文件。

| 模块 | 输出 |
|---|---|
| `bom.ts` | 型材按规格与下料长度归并；连接件按类型、系列及端盖截面归并，4040 B6 调节脚和转接件单独列出；核验型号紧固件配方、构件滑轨及铰链数量；独立及构件板材按尺寸、厚度和材质归并；实体行包含 `partNumbers` |
| `nesting.ts` | 按下料长度进行原料排料，计入锯口；每根原料的 `partNumbers` 与 `cuts` 一一对应；超长件单列为未满足，不计入原料及利用率 |
| `dxf.ts` | R12 ASCII，LINE/TEXT 分层；型材、连接件、独立板件及关闭构件板材三视图、整体尺寸和板材平面下料图；`PART_NUMBERS` 层包含编号及引线 |
| `step.ts` | AP214，以 `MANIFOLD_SOLID_BREP` 和封闭平面壳写简化实体，产品及实例的 id/name 使用零件编号，建立装配关系；构件按闭合板材导出，连接件采用显示模型的实体形状，曲面分面处理，保留实际通孔及深色实体，忽略明确的纯视觉标记；同一零件的多个实体归入一个产品，重叠部分不做布尔合并 |
| `assemblyHtml.ts` | 内联 SVG 和 CSS 的独立 HTML：关闭姿态概览、分步图、材料与下料清单；设备仅作虚线参考 |
| `shareLink.ts` | 列数组打包、deflate-raw、base64url，将设计写入 URL 片段；当前打包版本 9，保存设备占位、零件 ID、关联、`drawer`、`meeting`、端盖截面、内角码逐臂槽系和 `panelMount` 并兼容旧链接 |

BOM 的补件行是按对接端、自由端和已放置数量推算的建议。紧固件行保留来源中已核实的种类、长度及标准，未核验的规格不推导采购配方。DXF 和 STEP 包含简化连接件及已建模通孔，不含螺纹牙型、型材后加工孔、柜门铰链机构及拉手。

`partNumbers.ts` 从完整 ID 生成编号：型材、连接件、独立板件、构件分别以 `P-`、`C-`、`B-`、`F-` 开头，构件板件追加 `.B-` 和板件 key。ASCII 字母、数字和连字符原样保留，其他 UTF-16 码元转义为 `_XXXX`，保持大小写和唯一性。编号不依赖数组位置或尺寸；复制件使用新 ID，因此获得新编号。BOM 分组保留排序后的逐件编号，推算五金使用空编号数组。

装配 HTML 使用与界面相同的 `assemblySteps`，传入工程贯通规则并尊重固定端面；同位零件按 ID 排序。说明中的图形使用实体 OBB 的等轴投影，门抽关闭。按完整编号排序生成图示索引，图与表使用同一索引，图中标记链接到材料行。标题和设备名等文本转义后写入 HTML，无外部脚本、字体或图片依赖。

分享在浏览器内编码，不上传工程数据；链接保留设计和规则，以关闭姿态载入并保留零件 ID，不携带选择、撤销和日志。JSON 保留零件 ID 与开度。

## 开发、验证与部署

```bash
npm ci
npm run dev                       # Vite，默认 http://localhost:5173
npm test                          # Vitest，src/__tests__，Node 环境
npx playwright install chromium  # 首次运行浏览器测试时安装 Chromium
npm run build                    # TypeScript 检查和 Vite 打包，输出 dist/
npm run test:prod                 # Playwright，测试已构建的 dist/
npm run test:e2e                  # Playwright，开发服务完整 E2E
npm run test:all                  # 单元测试、构建、生产烟测及开发 E2E
docker compose up -d --build      # 生产静态站点，http://localhost:4174
```

开发 E2E 使用 `e2e/` 和 `playwright.config.ts`，自动启动严格端口 5174 的 Vite 服务，以无头 Chromium 和软件渲染运行，默认并行三个 worker。生产烟测使用独立的 `e2e-production/` 和 `playwright.production.config.ts`，在严格端口 4175 通过 Vite preview 运行预先构建的 `dist/`，使用一个 worker。它通过真实 UI 创建工作台、编辑零件、导入仓库示例、检查清单、自动保存、刷新恢复及 CSV 下载，并断言开发测试接口不存在。运行时保持被测源码和构建产物稳定。

两类测试分别将结果写入 `test-results/e2e/` 和 `test-results/production/`，失败时保存截图及 trace。本地可复用相应端口的服务，CI 必须自行启动服务。[CI 工作流](../.github/workflows/ci.yml) 使用 Node 24，依次执行 `npm ci`、单元测试、构建、生产烟测和完整开发 E2E；失败产物保留 7 天。

单元测试覆盖几何、编辑事务、存档、导出及仓库示例。`examples.test.ts` 检查家具工程的干涉、接头、角码落位、开合位置、层板承托和滑轨安装面；`exampleLayouts.test.ts` 核对示例开口和设备入口等布局。`connectorInstallation.test.ts` 检查双槽内角码的实际可用方向、完整孔组、三端面角块、补齐与占位及门板开度。连接件展示工程包含全部 14 类已安装件，逐一核验支承和实体干涉；家具工程另外检查全框架及各接头的连接图，避免孤立承托框。

编号测试核对保存、分享、重排、编辑及复制后的对应关系，并检查每根下料段可回溯到原件。装配 HTML 测试核对步骤覆盖、独立资源、文字转义和打印布局。STEP 测试核对文件引用、型材起点和下料长度，连接件几何范围，以及全部 14 类连接件在旋转和缩放后的封闭壳体和边方向；不构成外部 CAD 的兼容性保证。

开发模式或显式配置 `VITE_TEST_HOOK` 时，`window.__aluframe` 提供 store、工具状态、相机、屏幕坐标换算、拾取、接头及干涉等测试接口。

示例图片和 BOM 的生成方式见 [示例说明](../examples/README.md)。Docker 使用 `node:20-alpine` 和 `npm ci` 按锁文件安装后构建，`nginx:alpine` 托管 `dist/`；Compose 映射 `4174:80`，Nginx 使用静态路由回退及 gzip。
